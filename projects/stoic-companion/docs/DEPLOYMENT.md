# Deployment and operational limits

Start locally with the README's native commands or `docker compose up --build -d`. Compose binds PostgreSQL, Qdrant, API and frontend to loopback. It waits for PostgreSQL, runs Alembic, ingests snapshots, waits for API readiness, and then starts the frontend. PostgreSQL passwords are required environment values, never committed defaults. Use URL-safe local passwords or encode them before constructing a database URL.

Port conflicts can be resolved with `FRONTEND_PORT`, `BACKEND_PORT`, `POSTGRES_PORT`, and `QDRANT_PORT` in the Compose environment. Internal service ports remain unchanged. The verified WSL wrapper uses ports 3001/8001/5433/6334 and native Ubuntu Docker, independent of the broken Desktop backend. No factory reset was performed. `compose.wsl.yaml` shares a model-specific disk embedding cache with native smoke/evaluation commands while PostgreSQL/Qdrant/app data stay in named volumes.

The intended production configuration disables demo/debug, uses OpenAI embeddings, Auth0 RS256 API access tokens, PostgreSQL, Qdrant server and HTTPS behind a reverse proxy. Set the exact frontend origin. Public Auth0 client IDs are build-time frontend configuration; API keys/admin tokens are backend runtime secrets. The backend refuses production startup without its required identity/provider configuration. An Auth0 SPA uses PKCE through the official React SDK; there is no client secret in browser storage.

Run one API worker: its in-flight conversation set, minute rate limiter and cost reservation lock are process-local. Do not horizontally scale without shared atomic limits/reservations and idempotent request IDs. Monthly spend uses configured token-price estimates and recorded usage, not an invoice. Ingestion is an operator-controlled cost and query embedding can occur before a generation guard. Add provider hard caps. Native demo guest creation is not internet abuse protection; keep demo loopback-only. Add gateway throttles before exposing a public guest endpoint.

Use deployment-specific secure cookies if offering guest sessions under HTTPS (the supplied guest mode is local HTTP only). Apply log retention and privacy policies; user reflections are stored plaintext in SQL. Back up PostgreSQL and Qdrant together with source manifests and embedding model configuration. Deleting a conversation cascades its messages; usage records intentionally retain aggregate token/cost accounting without prompt text. Expired demo session cleanup and user/account deletion policy need an operator retention job.

Switching embedding model or chunking strategy requires a fresh versioned corpus/database; do not silently rewrite old citations. Source updates require manual rights/structure review and checksum changes. The CLI's deterministic point IDs and embedding cache make retries safe; a failed indexing job can be re-run. Admin ingestion is separate bearer authentication, disabled when ADMIN_TOKEN is empty, and should remain network-private even when configured.

Validated: full native WSL Compose startup, PostgreSQL migrations/connectivity, every app vector payload against SQL, live OpenAI embeddings/Responses and a browser conversation with source inspection/follow-up. Auth0 login still needs tenant/SPA configuration. The initial Alembic revision contains frozen explicit DDL. Generated prose validation blocks quotation/reference formats, retries a rejected structured answer at most once and accounts both calls, but does not prove semantic faithfulness. Review GPT prose before public launch. The keyword safety path is not a clinical risk classifier.
